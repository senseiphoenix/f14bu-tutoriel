Mapping HOTAS

Les planches annotées et cherchables de chaque périphérique, sur le modèle de celles du F-14B(U) : un bouton, sa commande DCS, le détail côté avion, et un lien vers la leçon qui s'en sert.

En cours — les fichiers existent, les données restent à construire

Le matériel est connu : même rig que le F-14B(U), moins les pédales — manche Virpil, manette MongoosT-50CM3, panneau WinWing PTO2. Les planches sont donc les mêmes images, déjà présentes dans le dépôt.

Le dossier d'entrées réel s'appelle Saved Games\DCS\Config\Input\F-4E-45MC\joystick\ — un seul dossier, pas deux : ni F-4E-Pilot ni F-4E-WSO comme la cascade du module le laissait supposer. Les 3 appareils utiles y ont désormais un fichier, avec leurs GUID lisibles.

Corrigé : le nom réel du dossier n'était pas celui prévu La cascade du module (Mods\aircraft\F-4E\Input\) expose deux profils, F-4E-Pilot et F-4E-WSO, ce qui laissait supposer deux dossiers séparés dans Config\Input\. Ce n'est pas ce que DCS a écrit : un seul dossier réel, F-4E-45MC, relevé le 19/08/2026. Exactement le genre d'hypothèse que la méthode du dépôt interdit — c'est la lecture directe qui a tranché, pas la cascade du module.

Ce qu'il faut faire pour débloquer

La même méthode que celle qui a servi pour le F-14B(U), consignée dans CLAUDE.md. Chaque étape produit une donnée vérifiée, jamais une hypothèse.

  1. Dire quel matériel sert à piloter le Phantom. Fait — même rig que le F-14B(U) : manche Virpil, manette MongoosT-50CM3, panneau WinWing PTO2. Confirmé dans les noms de fichiers de l'étape suivante : les GUID sont identiques à ceux du F-14B(U).
  2. Faire écrire les fichiers de binds par DCS. Fait — les 3 appareils ont un fichier dans F-4E-45MC\joystick\, avec une assignation chacun.
  3. Relire les vrais fichiers. Fait — le nom réel du dossier est F-4E-45MC (voir l'encadré ci-dessus), et les GUID des 3 fichiers joystick\<Nom {GUID}>.diff.lua sont lus.
  4. Extraire le catalogue de commandes du module avec la chaîne Lua du dépôt (tools/extract-commands.lua), en pointant la cascade d'entrées du F-4E — attention, elle est plus complexe que celle des autres modules : elle passe par bind_dsl.lua et bind_categories.lua plutôt que par un simple default.lua.
  5. Construire le mapping — un enregistrement par bouton et par axe, avec un statut explicite : correspondance confirmée, proposition à valider, ou pas d'équivalent. La taxonomie officielle du module est déjà disponible dans bind_categories.lua (Stick, Throttle, Radar Controls, Pave Spike, INS, RWR, Jester, Crew Chief Commands…) — la reprendre plutôt qu'inventer des thèmes.
  6. Récupérer les gabarits d'image des périphériques. Déjà disponibles — rig identique au F-14B(U) sur les 3 appareils utilisés, donc les planches existent dans le dépôt. Il reste à monter la page en réutilisant tel quel le moteur JS du F-14B(U) : seules les données changent.
  7. Générer les binds installables et valider chaque .diff.lua avec l'interpréteur Lua de DCS avant toute installation — après avoir sauvegardé le fichier existant.
